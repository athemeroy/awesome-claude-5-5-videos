# 调查方法与证据等级

本文记录的是 X 上**公开可检索、可取得媒体链接**的帖子样本。帖文提到 Claude Opus 5.5、展示视频，不等于视频由 Opus 独立生成，也不等于发帖人就是原作者。当前数字以[公开快照](../data/corpus-snapshot.json)为准；已发布的 X Article 保留其首版截点，本文和首页反映后续增量。完整原始收据保留在内部审计档案，本仓库仅发布可追溯的案例摘要。

## 发现帖子

使用 home Mini 上已有登录状态的 X 搜索，逐次查询模型全称、紧凑写法、one shot、动画／视频、制作技术、中文／日文／韩文／西文／法文，并交叉使用 Top、Latest 和 UTC 日期窗口。查询文本、成功状态与返回量汇总在[查询覆盖表](search-coverage.zh-CN.md)；原始返回与时间戳保留在内部审计档案。Grok 提供的原帖链接只作线索；每条纳入的线索均回读 X 原帖或线程确认作者、文字和媒体。发现的作者回复视频也保留原始帖子 ID。

首版 43 组检索后，9 月 25 日又做了 6 次增量查询：英语精确视频词、英语 video 与 animation、日语和中文表达。前五次成功，累计返回 189 条；第六次中文检索遇到 HTTP 429，保留失败收据，不计为成功覆盖。整轮产生 138 条此前语料未有的候选帖。`since:2026-09-25` 是 X 搜索的日期筛选词，命令行没有返回该查询实际采用的时区；例如一条 Top 结果的 UTC 时间为 2026-09-24 19:58。因此这里不把 `since` 日期当作精确 UTC 起点，保存帖文自己的 UTC 时间供回看。

另尝试了公开网页搜索与多引擎站点限定检索；公开搜索未返回可核实的新 X 原帖，多引擎入口数次超时。这些失败尝试不计入 X 查询覆盖，也不能据此推断没有漏帖。

主检索围绕模型发布前后；为了保留引用来源，还纳入少量早于发布的其他模型作品和参考片。它们只用于比较／溯源，不算 Opus 5.5 发布后的原创成片。

搜索结果中的“引用帖”有时自身没有 MP4，却嵌着原帖的视频地址。我们把能识别的原帖按其**原始帖子 ID**补入候选表，保留引用帖来源；这也会引入较早的参考片、其他模型的比较片或官方宣传片。它们被媒体检查覆盖，但只有读过原作者披露并符合主题的案例才进入解释性样本。

本次采集程序把每次搜索的返回上限设为 50 条，且遇到 HTTP 429。受检索排序、限流、账号可见性、删除或未索引帖影响，**候选总数不是 X 全站原作品总数**。以帖子 ID 去重，保留比较帖、教程、转述、游戏录屏及无关搜索噪音，以便显示检索边界；它们不自动进入原创作品结论。增量 Top 里有一条高互动西方文明视频，其 136.5 秒 MP4 与另一条标注 Opus 5.5 的转帖字节完全相同，但先发帖文只说“Claude”，未交代版本；我们保留帖子但不把这段视频升级为已核实案例。

## 逐片媒体检查

对 X 返回的每个直接 MP4 附件下载公开预览文件，使用 Hypit 0.2.3 的 `media probe` 记录时长、分辨率、帧率与音轨有无，用 `media tile --frames 9` 取得均匀分布的九帧图。每条帖子首个附件和同帖第二／第三附件有独立收据。缺少直接 MP4 的帖子标为 `no_mp4`；下载、探测或取样失败则保留失败状态，不算成功检查。所有媒体行与 Hypit 原始收据保留在内部审计档案；公开文件属性汇总见[媒体概况](media-profile.zh-CN.md)。

九帧图用于观察人物、版式、镜头和风格变化；它不能验收整段运动是否平滑、旁白发音、音乐同步、知识正确性或隐藏的工具调用。本次得到的 X MP4 很多是 480×270 左右的预览版，不能用它来判定作者上传的最高分辨率。中心帧分页索引用于人工扫视检索噪音；深读案例再查看完整九帧和原帖回复。

有一段 X 文件的容器／音轨标称时长长于最后可解码视频帧，按容器时长均匀抽样会在末段失败。我们先保留原始失败收据，再查视频帧时间戳，改在可解码的画面区间显式取九帧；该附件的收据记录了处理原因和时间点。媒体检查失败不会被默默算作成功，修复也不抹掉失败证据。

## 去重与分类

一条帖子可有多条 MP4；不同帖子也可能重新上传相同作品。SHA-256 仅能识别字节完全相同的文件，X 再压缩会使同一画面拥有不同哈希。内部候选表用时长与九帧相似度提示人工核对，**候选对不自动合并**，也不据此指认作者关系。报告分别给出候选帖、MP4 附件、不同 SHA 文件和深读案例的数量，不把任一个数字称作“原创电影总数”。

内部检索表的 `mentions_*` 是自动关键词命中，否定句、对比帖也可能命中，不能直接算工艺占比。Gemini 3.8 Flash 又对 1,138 个 SHA-256 不同的媒体样本，根据九帧和帖文分类；767 个标签为 yes、126 个为 likely、245 个为 no。该分类器做的是主题／画风归类与初筛，不预测传播量，也不能确认作者身份或模型调用。[公开案例表](../data/cases.csv)的 `primary_path` 才是人工深读案例的**单一主路径**；这 160 个案例刻意挑选了不同类型和证据条件，并非随机样本，不可外推成 X 全站各种视频工艺的比例。多个制作路径同时出现时，在逐案说明中列出实际分工。

## 证据等级

| 等级 | 具体材料 | 能说什么 | 不能说什么 |
|---|---|---|---|
| **媒体独立观察** | Hypit probe、九帧图、SHA-256、本地 MP4 | 取得的预览片长、文件属性、取样画面和文件是否重复 | 模型身份、完整声音质量、原始母版画质、隐藏制作过程 |
| **作者公开披露** | 原帖、同作者回复、公开提示词 | 作者如何描述输入、工具、耗时、修改和费用 | 这些步骤一定执行过，费用一定可复算，成片事实一定正确 |
| **公开工程佐证** | 相关仓库、可编辑工程、明确调用记录 | 对具体案例验证代码结构与部分生产路径 | 推及别的作者或未公开环节 |
| **分析推断** | 视觉与文字合并后的合理解释 | 提出值得核查的分类与限制 | 把外观当作渲染器指纹，或将推断写成确定事实 |

因此，文中“代码逐帧画”“外部视频模型做底片”“一轮”“零修改”等表述，都按原帖与工程证据具体标注；没有工程日志时保持“作者称”的口径。报告和公开索引不转载他人 MP4，发布时使用原帖链接或 X 的嵌入功能。
