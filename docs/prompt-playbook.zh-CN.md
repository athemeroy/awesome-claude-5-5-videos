# 七类可复用提示词：把制作路径讲清楚

这些是本次调查**重新编写的实验模板**，不是复制 X 作者的提示词。每类先列参考原帖及其公开条件，再给一个可替换主题的提示词。替换方括号后仍需人工核对源素材、事实、字幕和声音。不要把未实际使用的工具写进公开披露。

## 1. 零外部视觉素材的代码动画

参考：[@riku720720 的严格 Canvas 规格](https://x.com/riku720720/status/2102515058010132554)、[@x4b47x 的纸影剧场短片](https://x.com/x4b47x/status/2103019799614034026)。这类片的优势是风格可控、文字与几何关系清晰；角色表情、复杂自然运动与长片叙事需要额外审片。

```text
用 JavaScript + Canvas 2D 制作一支 [45] 秒、[9:16] 的短片，主题是 [主题]，面向 [受众]。
不要使用外部图片、视频、字体或视觉模型；可用的音效来源仅为 [自己生成的 Web Audio / 我提供并有权使用的音频列表]。
先给我 6–8 个镜头的分镜，每镜写明开始/结束时间、画面主体、动作、字幕和转场。确定一个角色造型与有限配色，在全片保持一致。
把画面绘制为确定性帧，输出一个可重复渲染的源文件和 MP4。先渲染前 5 秒样片，检查文字溢出、角色连续性和运动速度；修正后再渲染整片。最后列出确实使用的素材、代码文件、音轨和人工尚需复核的问题。
```

## 2. 教育讲解片：内容比视觉更重要

参考：[@LinearUncle 的 Manim + edge-tts 导数课](https://x.com/LinearUncle/status/2103128559174971663)、[@0x0funky 使用已有课程材料与 Remotion/CosyVoice](https://x.com/0x0funky/status/2102736587708854585)、[@Tz_2022 对音频试听边界的披露](https://x.com/Tz_2022/status/2102838830285898214)。特点是结构化图解容易生成，知识准确性与朗读质量仍需人检查。

```text
根据我提供的 [课程提纲/可信资料链接]，做一支 [3–5] 分钟的 [知识点] 入门视频。受众是 [年级/背景]；目标是让观众能解释 [三项学习目标]。
先列事实主张、来源和可能有争议或需要我确认的地方。再写逐镜讲稿与图解计划。画面用 [Manim/Remotion]，旁白用 [已配置的 TTS]，字幕由同一份时间轴生成。
导出 MP4、源代码、讲稿、来源清单和字幕文件。检查画面是否遮挡公式、字幕是否与时间轴一致、音轨是否存在且不削波；如果你不能真正听懂成片，请明确标记“旁白发音未由模型试听”，让我人工听一遍后再发布。禁止把未经核对的公式/史实当作确定事实。
```

## 3. 利用现有产品做宣传片

参考：[@freeman1266 的四张截图＋代码目录](https://x.com/freeman1266/status/2103144062467596689)、[@imthatcarlos 的既有组件/品牌＋Remotion](https://x.com/imthatcarlos/status/2102849219388133592)、[@jackfriks 直接指定应用分支里的角色素材](https://x.com/jackfriks/status/2103134485910892602)。这类片通常比空白委托稳定，但必须区分设计资产原作者与模型完成的部分。

```text
请根据这个产品仓库 [目录]、我提供的 [截图/品牌规范]，做一支 [20] 秒、[16:9/9:16] 的宣传片，目标观众是 [人群]。只能使用仓库中有权使用的图标、字体、截图和文案，不要自行编造产品功能、用户数据或评价。
先读代码与产品说明，列出实际可展示的三项能力；写 5 镜分镜，每镜一句核心信息和相应的真实界面证据。使用 Remotion 渲染，并保留可编辑工程。
先发低分辨率预览供我确认准确性，确认后输出 MP4。交付时列出复用的现有资产、模型新写的图形/动画、第三方音频和仍需法务/产品人员核实的说法。
```

## 4. 三维场景：把“建场景”与“拍电影”分开

参考：[@superalesha 的 Blender 质子对撞](https://x.com/superalesha/status/2102779758408774104)、[@dotey 多次打磨并寻找 3D 模型](https://x.com/dotey/status/2102940980379017293)、[@varga_bee 用参考片求解相机并用 Blender 渲染](https://x.com/varga_bee/status/2102744321355067761)。特点是材质和镜头可能很强，渲染耗时、资产来源、几何与物理正确性要另核对。

```text
在 [Blender/Three.js] 中制作 [主题] 的 [15] 秒三维镜头。先列出需要建模的物体、材质、光源、相机轨迹和每秒事件；标明哪些资产由你程序生成，哪些来自我提供的可使用文件。不要默默下载未经授权的模型。
先出灰模和镜头预览，再做最终材质/光照；保留工程文件及资产清单。最终输出 MP4，并把帧率、分辨率、渲染耗时、已知穿模/闪烁/物理问题写进交付说明。若展示的是实时交互场景录屏，请明确标成“演示录屏”。
```

## 5. Opus 做导演，视频模型做像素生成

参考：[@abxxai 的 Opus + Seedance 2.5](https://x.com/abxxai/status/2102775755646337530)、[@razeden0 的角色表/首帧/镜头规划](https://x.com/razeden0/status/2103153899431432535)、[@design_oyaji 的多工具 MV 流程](https://x.com/design_oyaji/status/2102899808788959580)。这类片能得到写实场景，但要写明视频模型和输入图片的贡献，不能标成“纯代码画每帧”。

```text
我有权使用以下素材：[概念图、角色图、音轨、品牌资料清单]。请你担任 [30] 秒视频的编剧与导演，最终片段由 [视频模型名称] 生成。
先设计角色连续性表、每镜首帧/末帧描述、镜头运动、节奏和声音计划；再为视频模型写逐镜提示词。每个镜头记录使用的参考图、模型与版本、生成次数和挑选理由。把片段剪成完整视频，检查人物/物件连续性、字幕和声音同步。
交付 MP4、分镜、提示词、素材来源、生成日志与实际服务费用。公开发布时，请写明“Opus 负责策划/编排；[视频模型] 负责生成画面”，并注明仍有人选片或修改的地方。
```

## 6. 基于现有影片的视觉改造与后期

参考：[@AxtonLiu 保留真人口播的声音、字幕与 83 秒时长](https://x.com/AxtonLiu/status/2102827887732932956)、[@aicreataro 用 After Effects 处理 MiniMax H3 原片](https://x.com/aicreataro/status/2102656273112326609)。这里的任务是识别源片结构、建立新旧画面对应关系，或制作可编辑的剪辑工程；源片贡献应在公开说明中保留。

```text
请以我提供且有权使用的 [原视频路径] 为唯一影像起点，制作 [目标风格] 的改编版。先探测片长、画幅、帧率、音轨与字幕，并列出我要求保持不变的要素：[原声/字幕/时长/人物身份/信息顺序]。
写一份逐时间段改造计划：原片中是什么、改编画面是什么、需要补画或修复的元素是什么。先做 10 秒样片，检查与原声和字幕的同步，再完成全片。若使用 After Effects，请交付可编辑工程及所用插件清单；若用代码覆画，请交付源码和渲染命令。
导出 MP4，并列出原片来源、外部视频/音频模型的实际使用、人工挑选或修订步骤。不要将源片中已有的表演、声音或图像说成从零生成。
```

## 7. 已有 skill／制作引擎的简短触发词

参考：[@Lucas_IA_ 先搭广告制作 skill、再用品牌和脚本触发](https://x.com/Lucas_IA_/status/2103152093733253544)、[@hanifproduktif 把匹配 32 秒蚂蚁短片的程序管线开源](https://github.com/buildwithhanif/claude-animation-skill)、[@makwired 的公开导演流程](https://github.com/klsoen/opus-js-animations)。简短任务可以高效复用成熟生产线，但要把预置系统、既有录音、声音服务和质量检查当作真实输入披露。

```text
请调用项目中的 [已命名的制作 skill／引擎]，为 [品牌／主题] 制作 [时长] 秒、[画幅] 的视频。脚本或事实材料在 [路径]，已授权的图片、logo、声音及字体在 [目录]。
开始前先列出该 skill 将调用的程序、渲染器、外部服务、已存在的模板和费用来源；检查脚本中的事实与品牌称谓，不能自行改写未经确认的产品声明。
按 skill 的既有流程做低清样片，抽查每个镜头的起中末画面和字幕／音频对齐；记录修订原因，再导出完整 MP4 和可编辑工程。交付时分别列出这次人类输入、预置 skill 及既有素材的贡献，避免把这条短触发词描述成空白环境中的完整制作说明。
```

## 一个不应跳过的公开说明

“one prompt”只说明最初的人类指令轮数；“纯代码”说明视觉渲染路径；“零外部素材”说明输入边界；“无人修改”说明审片和交付过程。四者独立，不能互相替代。[热门 12 小时 MV 的完整提示词](https://x.com/donaldjewkes/status/2102801469976248500)和 [@cherry_mx_reds 的短提示词截图](https://x.com/cherry_mx_reds/status/2102493305992880314)正好展示两种相反的输入形态。
