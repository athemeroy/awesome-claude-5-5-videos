# Claude Opus 5.5 适合做哪些视觉效果？

**研究截点：2026 年 9 月 27 日。** 这是一份制作决策指南，不是模型特效能力排行榜。我们把 Opus 5.5 看作能拆解需求、编写和修改制作代码、操作工具的代理；最终画面由浏览器、Canvas／SVG、Three.js、Blender、Manim、Remotion 或外部图像／视频模型等产出。Anthropic 的[模型规格](https://platform.claude.com/docs/en/models/opus-5-5/overview)列出文字与图片输入、文字输出；其[发布说明](https://www.anthropic.com/claude-opus-5-5)谈到程序图形表现，但不能据此推断它独自生成了案例中的视频像素。

下表的“适合”表示：任务可以被明确描述、由合适工具实现，并用可观察的结果迭代。这是基于[公开案例](../data/cases.csv)和制作方法作出的工程判断，**不是受控成功率、质量分数或与其他模型的优劣比较**。案例由创作者自述、公开工程和 X 预览样片提供不同层级的证据；[九帧取样](methodology.zh-CN.md)不能验证整段运动、音质、隐藏调用或物理准确性。

## 按任务选制作路径

| 任务族 | Opus 适合负责什么 | 需要的工具和输入 | 主要失效点与验收 | 何时改用或加入专门工具 |
|---|---|---|---|---|
| **产品界面、品牌动效、文字和形状转换** | 将产品信息拆成镜头、状态和时间线；写 SVG／Canvas／Remotion 动画，按反馈改节奏与排版。[Hooklab 案例](https://x.com/twoclipping/status/2102554209166000267)的公开规格包含实拍、产品 UI、逐拍分镜和帧检查。 | 真实 UI、品牌字形／颜色、授权字体和素材、可编辑工程。 | 文字溢出、品牌走样、形变跳切、首尾循环断裂；检查目标尺寸、关键帧、转场相邻帧与任意时间点 seek。 | 字体、品牌细节或复杂合成无法由代码稳定保持时，交给设计师和成熟动效工具精修；Opus 可继续做分镜与脚本。 |
| **流程、教学和数据图解** | 将给定事实转成清楚的步骤、图表、公式和旁白时间轴。[Manim 导数课](https://x.com/LinearUncle/status/2103128559174971663)和[长篇 Transformer 讲解](https://x.com/dotey/status/2103683057689522564)展示了这类工作流。 | 可靠的原始资料、数据／单位、Manim／SVG／Remotion，以及需要时的 TTS 和字幕工具。 | 画面完成但公式、数字、发音或字幕错误；逐条核事实和单位，人工试听整段音轨。 | 医学、法律、财务、工程或科学结论需要领域专家核对；复杂数值结果应由可复现计算提供，而非从画面猜测。 |
| **抽象图形、循环、音乐响应和程序绘画** | 写确定性的路径、粒子、笔触、关键帧与转场规则。[连续形变规格](https://x.com/leo_xiaolei/status/2102724347446305104)和有[公开角色 rig／逐帧工程](https://github.com/buildwithhanif/claude-animation-skill)的短片说明了规则与预置系统的重要性。 | Canvas／p5.js／WebGL、设计参考、音乐节拍或音轨、固定随机种子。 | 物体只是在画面上平移、镜头之间缺少连续变形、节拍错位；看连续帧条、循环接缝，并以不同顺序渲染同一时间点。 | 复杂表演、手部动作或强艺术指导需要角色 rig、人工动画或专业合成；已有歌曲、纹理和模板应算作输入。 |
| **交互式三维、产品漫游和空间可视化** | 构建相机、灯光、交互控件、动画状态和录屏／导出流程。[Clearwater 的公开 WebGL2 工程](https://github.com/Aureliengmz/clearwater)说明逼真的水面也可以来自实时着色器；[相机对焦实验台](https://x.com/RyanSael/status/2102591147927654847)展示可调的交互参数。 | Three.js／WebGL／Blender，明确的模型、贴图、字体、镜头和设备性能目标。 | 漂亮截图掩盖穿模、帧率下降、错误空间关系或资产来源不明；实际操作交互、换视角、测帧率并检查资产清单。 | 需要照片级建模、角色绑定或精细接触时，提供扫描／模型／rig 并使用专业三维制作流程。 |
| **风格化材质、纸艺、手绘和角色短片** | 建立可复用的样式规则、纹理、笔触、分层和镜头；在参考图与工程约束下逐段修订。[蚂蚁短片工程](https://github.com/buildwithhanif/claude-animation-skill)和[纸雕场景工程](https://github.com/klsoen/opus-js-animations)都包含预置系统或已有素材。 | 参考图、样式表、角色表与 rig、纹理和必要的音频素材。 | 第一张图好看，后续姿态、遮挡、表情和纹理却不一致；检查相邻帧和角色比例，并记录人工修订。 | 自然人物表演、复杂布料／毛发或需要精确表情时，用专业绑定、模拟、手工动画或合适的外部画面工具。 |
| **物理现象、自然运动与写实破坏** | 编排镜头、生成参数化示意、调用求解器、写导出和检查脚本；不要把“看起来像”写成“符合物理”。[LHC 场景](https://x.com/superalesha/status/2102779758408774104)的真实磁场轨迹是创作者声称，公开样片本身不能核实数据；[建筑倒塌流程](https://x.com/higgsfield_ai/status/2102863017109291059)明确组合了 Opus、Higgsfield 和 Blender。 | 已知方程／场数据、单位、边界条件、真实网格和材料参数；必要时使用 Blender 或其他专门的流体、刚体、布料求解器。 | 运动不守恒、碎片互穿、遮挡错误、模拟结果无法重复；用数值参考和完整时间轴核验，固定模拟缓存。 | 只需视觉比喻时可做受控图形；需要科研、工程或电影级物理时必须用经过校准的求解器和领域审查。[Blender 刚体缓存说明](https://docs.blender.org/manual/en/latest/physics/rigid_body/world.html)提供一种可复现路径。 |
| **真人与已有素材改编、外部视频模型镜头** | 处理分镜、镜头选择、字幕、剪辑、覆画与外部工具调度。一个[真人口播线稿重制](https://x.com/AxtonLiu/status/2102827887732932956)保留原声和表演；[多模型拼贴提示词](https://x.com/koldo2k/status/2103129347791986942)把不同画面和音乐任务交给外部模型。 | 授权原片／照片／音乐、人物和产品参考、视频模型或剪辑工具、明确的素材来源记录。 | 人物身份、口型、镜头连续性和声画同步不稳；看完整播放和音轨，核对授权、模型分工与最终镜头。 | 要求可靠的真人表演、精确产品镜头或跨镜人物一致时，优先用实拍／现有素材与专业后期；Opus 负责可审查的辅助工作。 |

**可复用制作系统的例子。** [Lemo-Opuscar](https://github.com/lemomo-ai/lemo-opuscar) 的 README 列出 39 种风格及对应短片，并公开[导演指南](https://github.com/lemomo-ai/lemo-opuscar/blob/main/DIRECTOR.md)、[技术指南](https://github.com/lemomo-ai/lemo-opuscar/blob/main/TECHNIQUE.md)和各风格说明。项目作者描述了代码逐帧渲染与两次人工批准节点。这能说明“简短触发词”可能依赖预先建立的风格库和制作规则；39 部成片的实际制作日志、逐片质量和“全代码”边界仍是作者披露，本文没有独立验收。

三个常见效果词可以帮助厘清验收目标：**“液态金属”**可能只要求反射与形变的设计感，也可能要求体积与表面张力正确；**“磁场”**可以是概念轨迹，也可以是要与场数据对照的科学可视化；**“碎裂”**可以是几何转场，也可以是材料断裂和刚体碰撞。先定目标，再选着色器、数学代码或物理求解器。单看一个 MP4 无法证明后一类准确性。

## 三阶段验收

1. **规格与关键帧。** 写明用途、观众要看懂的内容、画幅／时长／帧率、镜头与状态变化、不得变的文字或品牌元素、资产来源和物理／事实约束。先交付分镜和关键帧板；确认方向后再批量渲染。
2. **短动作样片。** 渲染最难的 2–4 秒，检查 12–24 张相邻帧、遮挡、接触、速度、循环接缝和字幕边界。对程序动画用固定种子与任意顺序 seek 复渲同一帧；对模拟先 bake／缓存。若宣称科学准确，另用参考数据和单位检查。
3. **整片与可复现交付。** 完整播放并试听，核片长、帧率、分辨率、文字、音量和声画同步；交付 MP4、可编辑工程、渲染命令、实际使用的素材／服务清单，以及仍未验证的主张。九帧索引适合初筛，不代替整片验收。

需要可直接填空的任务说明时，使用[七类制作路径提示词手册](prompt-playbook.zh-CN.md)。关键是把状态、素材和验收写清楚；短提示词可能只是触发已有 skill、代码库或人工准备的资产。

## 比较成本时记录同一交付标准

比较两条制作路径，应让它们完成**同一 brief、同一片长／分辨率、同一事实与视觉验收**，并分别报告以下项目：

| 记录项 | 应记录什么 | 易误读之处 |
|---|---|---|
| 模型使用 | 实际调用次数、输入／输出和缓存用量、实付账单；仅有公开价时标为估算。 | 每 token 价格、订阅额度消耗与整项任务费用不是同一个数。 |
| 外部工具与素材 | 视频／图像／TTS 服务的 credits 或账单、计算与渲染时间、付费素材和授权。 | “Opus 制作”不表示这些服务或既有资产为零。 |
| 人工与返工 | 准备参考、分镜审批、提示修订、失败渲染、事实核对、剪辑和最终审片的人工时间。 | 一次人类输入可触发大量模型调用与多轮内部检查；创作者自报工时需标明来源。 |
| 结果与时间 | 首版和验收版分别耗时多久、通过哪些检查、源工程是否可复用。 | 只比较首版速度或有无 MP4，会掩盖质量差异。 |

可以同时展示“现金支出”和“人工／机器耗时”；若要合成总成本，应公开人工时薪与计算计价假设。[@mablesjoseph 披露多次调用与人工参与](https://x.com/mablesjoseph/status/2103465246014746943)，说明短片也可能经历长时间迭代；这些是作者口径，不是独立账单或模型基准。
